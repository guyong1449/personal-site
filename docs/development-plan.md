# GUYONG 后续功能开发计划

更新于 2026-08-31。本文件是后续开发的唯一状态源；`remaining-tasks.md` 只保留
当前短清单。计划以“先保证内容不会丢、不会误发布，再增强展示体验”为顺序。

## 1. 已确认的当前基线

- 公共站点已有 `/`、`/notes`、`/gallery`、`/archive`、`/search`、
  `/account`、Note/Gallery 详情、RSS、Sitemap、robots 和 404 页面。
- Studio 仅监听 `127.0.0.1:4319`，生产环境没有 `/studio`，继续保持本机写作边界。
- `.local-content` 保存本机草稿、历史和草稿资产；`content/site` 是正式内容源；
  `content/public` 由 `site-builder` 生成，禁止手工修改。
- Studio 已有新建、导入、自动保存、历史版本、图片压缩、封面、定时发布、发布、
  下线和永久删除的界面与基础实现；发布/下线恢复、资产冲突和定时任务已有定向测试。
- GitHub 已连接 Vercel，`main` 是生产分支；提交 `3318dbc` 已完成自动部署验证。
- 当前正式内容为 1 篇 Note，Gallery 仍为空；因此 Gallery、真实封面和下线 404
  尚未完成生产验收。
- 当前质量门已包含 site-builder、Studio、Legacy publisher、Web 测试，Web typecheck、
  构建后 smoke、站内链接和生成快照一致性也已接入 `pnpm verify`。仍缺少完整浏览器
  E2E 和真实生产内容的线上冒烟覆盖。

## 2. 开发原则与产品边界

- Studio 是唯一主写作入口；Legacy Obsidian publisher 只保留迁移兼容，不继续扩展。
- 发布只处理当前内容及其资产，不允许宽范围暂存、自动提交整个工作区或隐式覆盖其他内容。
- 已发布内容改 slug 时，先下线、再改名、再发布；不在后台偷偷保留两个正式 URL。
- 原始 HTML 不进入内容契约；Note 使用 `content_type: note`，课程语义继续使用
  `course/*` 标签；Gallery 保持独立类型。
- 不引入数据库、远程 CMS、多人账号、外部搜索或统计，除非内容规模和使用场景证明需要。
- 每个代码批次完成后运行 `pnpm verify`；外部上线批次还必须核对同一提交的 CI、
  Vercel SHA 和线上路由。

  slug 冲突和确认覆盖的 API 测试。
- [x] 允许从已发布快照建立本机草稿并继续编辑，完整保留置顶、定时、Gallery 分类/系列。
- [x] 修改 slug 后保存应返回新 slug；发布必须使用新 slug，保存失败必须立即停止发布。
- [x] 已上线内容不能从“永久删除草稿”接口绕过下线流程。
- [x] 自动保存不生成历史快照；手动保存和恢复继续保留版本。
- [x] 下线回草稿时完整保留 frontmatter；已有本机草稿时保留本机编辑并明确提示。

自动保存和下线行为符合上述规则；自动同步在脏工作区明确跳过；全仓 `pnpm verify` 通过。

### P0-B：事务恢复与 Git 提交隔离（2026-08-30 已完成）

- [x] 发布/下线前保存操作清单和文件备份；在生成、检查、提交失败时自动回滚本地正式层，
  不留下“正式稿已删但流程失败”的半完成状态。
- [x] 发布前检查受管内容路径是否已有改动；只暂存当前 slug、当前引用资产、三份生成索引和
  RSS，不允许把另一篇未完成内容带入提交。
- [x] 资产同名但内容不同不得覆盖其他文章正在使用的文件；冲突会在修改正式层前拒绝。
- [x] 为生成失败、测试失败、提交失败和推送失败增加故障注入测试，证明草稿和备份可恢复。

验收：测试仓库内准备两篇并行改动，只发布其中一篇时提交中不得出现另一篇；任一失败点
都能恢复到操作前文件状态，并给出明确的下一步修复指引。

验收：记录两个提交 SHA、两次 Vercel 部署和线上 200/404；整个过程不使用永久删除。
